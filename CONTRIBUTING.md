# Contributing to AI Blueprint Model

Thanks for contributing to ABM.

## Repository principles

- **Simplicity first**: prefer plain files and direct conventions.
- **Composable by default**: design parts that can be reused across blueprints.
- **Readable in git**: optimize for line-by-line review and clear diffs.
- **Operationally practical**: include guidance that supports repeatable workflows.
- **Markdown-first**: prioritize human-readable source over opaque tooling.

## Design philosophy guidance

When proposing changes, aim for:

1. **Clarity over cleverness**
2. **Explicit contracts over hidden assumptions**
3. **Extensible structure over rigid frameworks**
4. **Stable conventions over ad hoc patterns**

## What to avoid

- framework bloat
- unnecessary abstraction layers
- hidden magic or implicit behavior
- automation that removes inspectability

## Recommended contribution flow

1. Open an issue or draft proposal.
2. Keep scope narrow and focused.
3. Include concrete examples when changing specification language.
4. Prefer additive changes for compatibility.
5. Ensure docs and examples stay aligned.

## Pull request expectations

- Explain what changed and why.
- Update related documentation.
- Keep changes minimal and reviewable.
- Preserve markdown readability.
