# evaluations.md guidance

## Purpose

Translate blueprint expectations into a review rubric.

## Recommended sections

- pass/fail checks
- quality dimensions
- common failure modes
- reviewer notes

## Authoring guidance

- map evaluation criteria back to outputs and constraints
- keep scoring or review language simple enough for consistent use
- document failure modes that are likely in real workflows

## Common pitfalls

- introducing new requirements that do not appear elsewhere in the blueprint
- writing evaluation criteria that are too abstract to apply consistently
