# inputs.md guidance

## Purpose

Define the information required or preferred before generation starts.

## Recommended sections

- required inputs
- optional inputs
- input assumptions
- missing-information handling

## Authoring guidance

- describe inputs in the language blueprint authors and reviewers already use
- distinguish mandatory context from nice-to-have context
- make missing-data behavior explicit when it affects output quality

## Common pitfalls

- mixing input descriptions with output requirements
- hiding critical source dependencies in prose elsewhere
