# components.md guidance

## Purpose

Define reusable building blocks that can be composed into final assets.

## Recommended sections

- named components
- role of each component
- reusable patterns or snippets
- composition notes

## Authoring guidance

- capture repeatable blocks rather than full finished assets
- explain how components support both content and style goals
- keep component definitions reusable across related outputs

## Common pitfalls

- storing complete examples instead of reusable components
- creating component names that are too vague to reuse
